# M12: harness-handoff skill (cross-agent session handoff) — Implementation Plan

**Goal:** Add a fourth skill, `harness-handoff`, that verifies the
session-end ritual (clean tree, green gate, logged session) and prints a
paste-ready prompt for the next agent — any vendor (Claude Code, Codex,
Cursor, …). This turns the multi-agent "shift work" pattern from a habit
into a mechanical check. Released as plugin 1.3.0.

**Architecture:** Same two-layer pattern as harness-status: a deterministic
script (`skills/harness-handoff/scripts/handoff.sh`) plus a thin SKILL.md
judgment layer. Unlike status.sh, handoff.sh **does** use git (a clean tree
is the point), so fixtures are tiny git repos. Boundary kept sharp:
**status = "how is the work going?", handoff = "is the repo safe to hand
to the next agent, and what do I tell it?"**.

**Tech Stack:** bash + jq + shellcheck (same as existing checkers).

## Contract (handoff.sh)

`handoff.sh [--skip-gate] [TARGET_DIR]` — read-only.

Exit codes:
- `0` — HANDOFF READY; prompt printed between `== Prompt` markers.
- `1` — HANDOFF BLOCKED; one `BLOCKED:` line per unmet ritual step
  (dirty tree, red/missing gate).
- `2` — harness file broken/missing (bad FEATURES.json, no AGENTS.md) →
  names harness-audit.
- `3` — not initialized → names harness-setup.

Prompt content: next failing feature (same lowest-milestone/lowest-id jq
selection as status.sh), its verify criterion, the one-session rules
(gate before/after, test-first, legal flip, PROGRESS.md entry, STOP).
References `docs/agents/harness-protocol.md` section 2 when the target has
it, plain AGENTS.md session loop otherwise. Nothing failing → planning
prompt (protocol section 1) instead. `--skip-gate` skips the gate run but
prints a `WARNING: gate not verified` line.

## Decision log

- **2026-07-11 — handoff.sh uses git; fixtures are git repos.** A clean
  tree is the core ritual check; status.sh's git-free choice doesn't
  carry over. Fixture cost is three extra lines per fixture.
- **2026-07-11 — gate runs by default, `--skip-gate` to opt out.**
  Inverse of status.sh's `--run-gate`: for status the gate is optional
  color; for handoff the gate IS the trust boundary, so skipping must be
  explicit and shouted (WARNING line), never silent.
- **2026-07-11 — missing AGENTS.md is exit 2 (broken), not a warning.**
  The generated prompt's first instruction is "Read AGENTS.md"; without
  it the handoff cannot work, and every scaffold ships one.
- **2026-07-11 — empty PROGRESS.md does not block.** A freshly scaffolded
  repo has no session entries yet but is perfectly handable; blocking
  would break the setup → first-Codex-session flow.
- **2026-07-11 — prompt stays agent-neutral.** No vendor names inside the
  generated prompt; Codex-specific feeding instructions live in README
  and SKILL.md, not in handoff.sh output.
