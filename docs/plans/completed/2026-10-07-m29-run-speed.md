# M29: Faster runs from a real run's findings

**Goal:** a run spends its time building features, not re-proving green
trees or rediscovering blockers.

**Why:** troubleshooting a real run found: every builder re-ran a full
baseline gate on a tree the previous builder had just proved green (~1.5
min per feature); a feature needing production approval took 14 minutes to
be found blocked, and a skipped feature is retried on the next run; most of
the remaining time is model round-trips, which nobody measured per feature.

## M29-001 — Reuse a proven-green baseline

- `run-gate.sh` records, after every green run, a fingerprint of the files
  it proved (git tree of the working tree, ignored files out, PROGRESS.md
  and docs/plans/ out) in the clone's git dir; a red run deletes it.
- `run-gate.sh baseline` on a clean tree whose fingerprint matches prints
  `GATE: green (baseline reused: …)` and does not run the gate.
  `HARNESS_GATE_REUSE=0` forces a full run. FEATURES.json stays in the
  fingerprint (gates may check it).
- Protocol §2.3: a reused baseline counts as green.

## M29-002 — Waiting on a human

- A feature that needs a human (approval, credentials, production access)
  is `deferred` with notes starting `Needs a human: <question>`. Planning
  asks it per feature (§1.4); a session that stops on a Needs-a-human item
  defers its own feature that way, so no later run retries it.
- status.sh lists `WAITING ON HUMAN: <id> — <question>` and holds failing
  features whose `depends_on` reaches one (`HELD: <id> — depends on <id>`),
  in both modes. The run report has a "Waiting on a human" section.

## M29-003 — Start from the paths; measure each feature; release 3.7.0

- status.sh prints `paths:` under `NEXT:` when the feature has them;
  harness-run passes them to the builder as where to start reading.
- The run report shows minutes per done feature (from commit times) and
  tokens (from `.harness-run/tokens.log`, written by the Claude Code
  edition's budget guard at each SESSION line).
- CHANGELOG 3.7.0, manifests, mirror sync, CI green.
