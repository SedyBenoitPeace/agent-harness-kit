# M68-002 — upgrade-all.sh finds the harnessed repos in a folder

Owner (2026-11-23): listing each repo by hand is still manual work, and a
repo harnessed later is missed. The script should take the folder that
holds the repos, ask for it once, and find the harnessed ones on each run.

## Behaviour

- A list line that is a directory but not a git repo's top level is a
  folder: it stands for each directory directly inside it that is a git
  repo's top level and has `FEATURES.json` and `PROGRESS.md`, in sorted
  order, never the kit's own repo. Each found repo then runs as a listed
  repo does today (one result line each). Other children print nothing.
  A folder with no such repo: `<folder>: skipped: no harnessed repos inside`.
  One level only, no recursion. A line that is a repo behaves as before.
- `--add DIR`: resolve DIR to an absolute path (it must exist; a leading
  `~/` is expanded), append it to the list unless already there (creating
  the list), print `added: <path>`, exit 0 without upgrading anything.
- No list and stdin is a terminal: ask `Folder that holds your repos: `,
  add the answer exactly as `--add` does, then carry on with the run. An
  empty answer or a missing folder: exit 2. No list and no terminal (an
  agent, CI): exit 2 as today, the message now naming `--add <folder>`.

## Test (added to `scripts/test-upgrade-all.sh`)

7. A folder holding an outdated harnessed repo, an unharnessed git repo
   and a plain subfolder, listed as one line, `--dry-run`: exactly one
   result line, `would open a PR` for the harnessed repo.
8. An empty folder as a line → `skipped: no harnessed repos inside`.
9. `--add` twice with the same folder → the list has it once, absolute;
   `--add` of a missing folder → non-zero exit, list unchanged.
10. A folder line that contains the kit's own checkout does not list it
    (unit-level: point the script's kit detection at a fixture if the real
    kit cannot sit in the temp folder; say how it was checked).

The terminal prompt reuses the `--add` code path; the prompt itself is not
covered by the test (no terminal in the gate).

## Decision log

- 2026-11-23: one level, no recursion: a deep scan of a source folder walks
  dependency folders and finds vendored repos.
- 2026-11-23: `--add` beside the prompt, so an agent with no terminal can
  set the list too and the logic is testable.
