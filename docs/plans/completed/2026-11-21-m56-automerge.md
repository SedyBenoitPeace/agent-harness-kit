# M56: the agent merges its own PR when the rules allow (zero-touch QA phase 2)

Decisions 12–15 in `docs/decisions.md`.

## Config (FEATURES.json, top level, optional)

    "automerge": {"enabled": true, "protected": ["<regex on paths>", ...]}

Absent = enabled with the default protected list (`can-merge.sh --list`):
`.github/`, auth, migrations, secrets and keys, dependency manifests and
lockfiles, deploy config. `enabled: false` is the repo's off-switch.
Per feature: `"automerge": true` (granted in the brief; absent = no).

## M56-001 can-merge.sh

`skills/harness-session/scripts/can-merge.sh <pr> [--merge]` (grants and config read from the base branch; merge pinned to the checked head; gate files always protected) prints `MERGE`,
`WAIT` (checks still running, exit 3) or `HOLD` (exit 1) and the reasons.
MERGE needs all of: repo enabled; PR open, mergeable, label `harness:agent`;
every feature id (`M<n>-<nnn>`) in the PR title and body exists and has
`automerge: true` (at least one); CI checks all passed, or with no checks
the gate (`scripts/e2e.sh`) green on the PR head checked out; no changed
path matches a protected pattern; no test file deleted and no skip/only/
fixme added in a test file. `--merge` runs `gh pr merge --merge
--delete-branch` only on MERGE. `--list` prints the protected patterns.
Tested against a fake gh (`scripts/fixtures/merge/gh`).

## M56-002 agents and the brief

Brief: `## Automerge` yes or no (check-brief.sh fails anything else);
planning copies it to `automerge`. Builder and protocol 2.6: agent PRs get
label `harness:agent`; run `can-merge.sh --list` before editing and say in
PROGRESS when the feature must touch a protected path (the PR will wait);
after the PR is green, run `can-merge.sh <pr> --merge` and report its first
line.
