# Brief: Live run board

## Objective
During a harness-run or harness-continuous run, a self-refreshing local page `.harness-run/board.html` shows every feature's stage, agent, gate and cost for any CLI (Claude Code, Codex, Copilot), opened once automatically, with no extra assistant tool calls per feature.

## Stage
Production: the kit is published and used daily by its owner on real runs; a broken script here can stop a run.

## Context
- Run state already on disk, written by scripts with no model calls: `FEATURES.json` (`status`, `eval_attempts`, `notes`), `.harness-run/start` (start commit), `skip`, `busy`, `STOP`, `results/<id>.txt` (first line `SESSION: <id> · <passing|review|blocked> · gate <green|red> · <commit|reason>`), `models.log`, `usage.log`, `cost.log`, `so-<cli>-<id>.txt`, lane worktrees `../<repo>-<id>` on branch `lane/<id>`.
- Scripts each run already calls: `skills/harness-run/scripts/run-start.sh` (today only harness-continuous calls it), `dispatch.sh` (once per feature, both modes), `second-opinion.sh`, `run-report.sh` (continuous end), `skills/harness-session/scripts/run-gate.sh` (builders, baseline and final), `skills/harness-session/scripts/context.sh` (loop start, both modes), `skills/harness-status/scripts/status.sh` (verify step).
- Gap: `dispatch.sh` logs to `models.log` only for codex and copilot, so on Claude nothing on disk says a feature is building; no stage has a timestamp.
- Kit style: bash + jq, no other runtime; tests are `scripts/test-*.sh` run by `scripts/e2e.sh`.

## Deliverables
- **Run identity.** `run-start.sh` also writes `.harness-run/run-id` (`<epoch seconds>-<pid>`), deletes `board-opened`, and archives `events.log` with the other logs under `previous/<previous run-id>/` (falling back to `previous/<its start commit>/` when the previous run has no `run-id`, as today). Two runs on the same HEAD are still two runs, and their archives never collide.
- **`.harness-run/events.log`**, one line per event, `<epoch seconds> <event> <id or -> <fields>`, written only when `.harness-run/start` exists in the main repo (scripts in a lane worktree find it with `git rev-parse --git-common-dir`):
  - `dispatch <id> <cli> <agent> <size>` from `dispatch.sh`, every CLI, Claude included;
  - `gate <id or -> <baseline|final> <start|green|red>` from `run-gate.sh`; the id comes from the current branch when it is `lane/<id>`, else `-`;
  - `opinion <id> <cli> <PASS|NEEDS_WORK|REJECTED>` from `second-opinion.sh`;
  - `run-start - <start commit>` from `run-start.sh`, `run-end - <reason>` from `run-report.sh`.
- **`skills/harness-run/scripts/board.sh <target> [--open]`** writes `.harness-run/board.html` atomically (temp file + mv). bash + jq only.
  - Rows: every feature not `passing` in `git show $(cat .harness-run/start):FEATURES.json`, plus every feature that turned `passing` since. Archived features are not shown.
  - A result file is *current* when its mtime is at or after (`>=`, whole seconds) the feature's latest `dispatch` event, or when the feature has no dispatch event. A stale result file (from before a redispatch) is ignored for stage, gate and time.
  - Stage per row, first match wins: `skipped` (id in `skip`); `passing` (FEATURES `passing`); `gate running` (latest gate event for it is `start` and it has no current result; a `-` gate event belongs to the one dispatched non-lane feature with no current result); `building` (has a dispatch event and no current result; tagged `lane` when `../<repo>-<id>` exists); `blocked` (current result says blocked); `review` (FEATURES `review`, or current result says review); `rework (n/2)` (FEATURES `failing` with `eval_attempts` n > 0); else `queued`. M54-001: with no `run-end` and no on-disk activity (events.log, results, quiet.sh logs in main and lanes) for `HARNESS_BOARD_STALE` seconds (default 1800), `building` and `gate running` show `stalled`, the header says `run stalled: no activity for <dur>` and the Stop button becomes `no live run`.
  - Gate column: while building, the latest gate event for that feature; after a result, the result file's `gate <green|red>`; else `—`.
  - Time in stage: `building` from its latest dispatch event, `gate running` from its gate start event, `review`, `passing` and `blocked` from the current result file's mtime (for `passing` with no result file, `—`); `—` for `queued`, `skipped` and `rework`. Opinion events start no stage; they only fill the expanded row.
  - Cost column: the sum of `cost.log` lines `<id> <usd>` for that id as dollars; when there are none, the sum of `usage.log` input + output fields (`<scope> <cli> <model> <input> <cached> <output>`) for scopes `<id>` or `<id>/...` as tokens (`1.5M tok`); else `—`. The header sums the same way.
  - Agent column: CLI, agent and size from the latest dispatch event, plus the model from `usage.log` when present.
  - Header: repo, branch, run start time, progress bar, counts per stage, cost so far, "updated N s ago", and "run ended: <reason>" after a `run-end` event.
  - A row expands to the feature's `notes`, its result file's lines and its second-opinion verdicts.
  - The page reloads itself every 5 s with inline JS, keeps expanded rows across reloads (`sessionStorage`, wrapped in try/catch), and ticks time in stage from embedded timestamps. Self-contained: no network, no external assets, light and dark via `prefers-color-scheme`.
- **`--open`** opens the page once per run: when `.harness-run/board-opened` does not hold the current `run-id`, it runs the opener (`$HARNESS_BOARD_OPEN_CMD` when set, else `open` on macOS, `xdg-open` on Linux, else none), records the run-id, and prints `BOARD: <absolute path to board.html>`. With `HARNESS_BOARD_OPEN=0` it prints the `BOARD:` line and opens nothing. Without `--open` it prints nothing.
- **Wiring.** Each call is the script's last step, as `bash "<dir>/board.sh" <target> >/dev/null 2>&1 || true`, and never changes the caller's exit code. Callers `dispatch.sh`, `second-opinion.sh`, `run-gate.sh`, `context.sh` and `status.sh` call it only when `.harness-run/start` exists in the main repo and the latest `events.log` line is not `run-end`. Two exceptions skip that `run-end` check: `run-report.sh` calls it right after writing `run-end` (the final snapshot), and `run-start.sh` calls `board.sh --open` and passes through only its `BOARD:` line to stdout.
- **Skills.** `skills/harness-run/SKILL.md`: the interactive run calls `run-start.sh` once at its start, as harness-continuous already does. Both `harness-run` and `harness-continuous` SKILL.md say to put the `BOARD:` line from `run-start.sh` in the first progress line shown to the human.
- **Tests and docs.** `scripts/test-board.sh`, run by `scripts/e2e.sh`. The `harness-protocol-runs.md` template, README and CHANGELOG describe the board, `HARNESS_BOARD_OPEN` and `HARNESS_BOARD_OPEN_CMD`. Version 3.21.0 in AGENTS.md (state line), CHANGELOG.md, package.json, `.claude-plugin/plugin.json`, `.claude-plugin/marketplace.json`, `claude/.claude-plugin/plugin.json` and `scripts/e2e.sh`, bumped once, in M47-002 only.

## Non-goals
- No server, no terminal table, no status-line output, no per-CLI hooks.
- No pull request or CI state.
- No progress from inside a builder between its dispatch and its gate.
- No `run-end` for interactive harness-run (it never calls `run-report.sh`). Its page keeps refreshing on later script calls and shows "updated N s ago".
- No Windows opener (the `BOARD:` path is still printed).
- No rotation or size cap on `events.log` beyond the per-run archive.
- No change to the FEATURES.json schema, the `results/<id>.txt` format, `cost.log` or `usage.log` formats, the Claude Code edition in `claude/`, or superfan.

## Done when
- `bash scripts/test-board.sh` exits 0, proving on a fixture repo:
  - `run-start.sh` stdout contains `BOARD: <abs path>/.harness-run/board.html`, the file exists, and `HARNESS_BOARD_OPEN_CMD` (a script that appends to a counter file) ran exactly once;
  - a later `dispatch.sh` or `status.sh` in the same run leaves the counter at 1;
  - a second `run-start.sh` on the same HEAD raises the counter to 2 and moves the previous `events.log` into `previous/<first run-id>/`; a third on the same HEAD archives into a different `previous/<second run-id>/` and the first archive is unchanged;
  - `HARNESS_BOARD_OPEN=0` leaves the counter unchanged and still prints `BOARD:`;
  - after `dispatch.sh <target> claude <id>`, `events.log` has a `dispatch <id> claude` line and the row shows `building`;
  - a `run-gate.sh final` call on branch `lane/<id>` in a linked worktree writes `gate <id> final start` to the main repo's `events.log`, and the row shows `gate running`;
  - a result file with `review` shows `review`; a stale `review` result file (older than its latest dispatch) plus FEATURES `failing` with `eval_attempts` 1 shows `rework (1/2)`; redispatching that feature (dispatch event newer than the stale result) shows `building`; a result written in the same second as its dispatch counts as current; FEATURES `passing` shows `passing`; `failing` with `eval_attempts` 1 shows `rework (1/2)`; an id in `skip` shows `skipped`; a `cost.log` line shows its dollars; a `usage.log`-only feature shows tokens;
  - with `board.sh` replaced by a script that prints junk and exits 1, `dispatch.sh`, `status.sh` and `context.sh` give the same exit code and stdout as with no board;
  - with no `.harness-run/start`, `context.sh`, `status.sh` and `run-gate.sh` write neither `board.html` nor `events.log`;
  - after `run-report.sh`, the page says `run ended`, and a later `status.sh` does not rewrite `board.html` (same mtime);
  - bash's `time` builtin (`TIMEFORMAT=%R`) on `board.sh` with a 60-feature fixture reports under 1.0 s locally; under `CI=1` the limit is 3.0 s.
- `grep -c 'run-start.sh' skills/harness-run/SKILL.md` prints at least 1, and `grep -c 'BOARD:'` prints at least 1 for each of `skills/harness-run/SKILL.md` and `skills/harness-continuous/SKILL.md`.
- `bash scripts/e2e.sh` exits 0.
- `bash scripts/ci-local.sh` prints `CI-LOCAL GREEN`.

## Quality bar
Gate is sufficient, plus the opened page read by a person once on a real run.

## Needs a human
- None during the build. After merge, the owner opens the page on one real run to judge the look.

## Budget and stop condition
At most 2 features: M47-001 is run identity, `events.log` and `board.sh` with its tests; M47-002 is the wiring into the run scripts and skills, docs and version. Built with harness-continuous. Stop at the milestone boundary; a red gate skips the feature as harness-continuous does.
